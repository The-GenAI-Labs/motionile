# Database schema blueprint

This is the complete design of every table Motionile will have. Each phase migrates exactly the tables marked with its number, as written here. A later phase that needs to change a table updates this file in the same pull request as its migration.

Read [`conventions.md`](conventions.md) first; this file assumes it. Diagrams live in [`erd.md`](erd.md), status transitions in [`state-machines.md`](state-machines.md), purge rules in [`retention.md`](retention.md).

## How to read this file

- **Type** is the Postgres type. `uuid` primary keys are UUIDv7 generated by `motionile.core.ids.new_id()`; they have no database default.
- **Null** is `no` for `NOT NULL` columns.
- **Default** is the database default. A dash means none. `now()` is evaluated by Postgres; `updated_at` is also set by the ORM on every update.
- **On delete** for foreign keys is always explicit. `NO ACTION` is used where a reference must block deletion of its target but both rows can be removed by the same cascading statement (for example, a user deletion that cascades through two paths); Postgres checks `NO ACTION` at the end of the statement, while `RESTRICT` would fail midway.
- **Deferred foreign key** means the constraint is created after both tables exist (`use_alter`) and is `DEFERRABLE INITIALLY DEFERRED`, so circular references can be written in one transaction.
- **Added by phase N** on a foreign key means the column exists from its table's phase, but the constraint is added by the phase that creates the referenced table.
- Every index lists the query it serves. Indexes that exist only to support a foreign key say so.
- Constraint and index names follow the naming convention and are the exact names the migrations use.

## Platform (core)

### `audit_log`

Module `audit` · Phase 2 · **Append-only** · Will be partitioned monthly (see `retention.md`)

Records security-relevant and administrative actions. Written only through `motionile.modules.audit.record()`.

| Column          | Type          | Null | Default | Notes                                                                                        |
| --------------- | ------------- | ---- | ------- | -------------------------------------------------------------------------------------------- |
| `id`            | `uuid`        | no   | -       | UUIDv7                                                                                       |
| `actor_user_id` | `uuid`        | yes  | -       | Who acted; null for `system` actors and after the user is purged                             |
| `actor_type`    | `text`        | no   | -       | `user`, `admin`, `system`, `api_key`                                                         |
| `action`        | `text`        | no   | -       | Dotted verb such as `auth.login.succeeded`, 3 to 100 characters                              |
| `target_type`   | `text`        | yes  | -       | Kind of object acted on, such as `user` or `order`, at most 64 characters                    |
| `target_id`     | `text`        | yes  | -       | Identifier of the target, at most 128 characters; text because some targets have string keys |
| `ip`            | `inet`        | yes  | -       | Client IP as seen through the trusted proxy                                                  |
| `user_agent`    | `text`        | yes  | -       | Truncated to 512 characters                                                                  |
| `request_id`    | `text`        | yes  | -       | Correlates with logs, at most 64 characters                                                  |
| `metadata`      | `jsonb`       | no   | `'{}'`  | Structured details; never secrets                                                            |
| `created_at`    | `timestamptz` | no   | `now()` |                                                                                              |

Keys and constraints:

- `pk_audit_log` primary key (`id`).
- `fk_audit_log_actor_user_id_users` → `users.id` **ON DELETE SET NULL**, added by Phase 4.
- `ck_audit_log_actor_type`: `actor_type IN ('user', 'admin', 'system', 'api_key')`.
- `ck_audit_log_action_format`: `action ~ '^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$' AND char_length(action) BETWEEN 3 AND 100`.
- `ck_audit_log_target_type_length`: `target_type IS NULL OR char_length(target_type) <= 64`.
- `ck_audit_log_target_id_length`: `target_id IS NULL OR char_length(target_id) <= 128`.
- `ck_audit_log_user_agent_length`: `user_agent IS NULL OR char_length(user_agent) <= 512`.
- `ck_audit_log_request_id_length`: `request_id IS NULL OR char_length(request_id) <= 64`.
- `ck_audit_log_metadata_object`: `jsonb_typeof(metadata) = 'object'`.
- Trigger `trg_audit_log_append_only` `BEFORE UPDATE OR DELETE` → `forbid_append_only_mutation()`.

Indexes:

- `ix_audit_log_created_at_id` (`created_at`, `id`): admin audit list, newest first, keyset pagination.
- `ix_audit_log_actor_user_id_created_at` (`actor_user_id`, `created_at`): "what did this user do"; also supports the foreign key.
- `ix_audit_log_target_type_target_id_created_at` (`target_type`, `target_id`, `created_at`): history of one object.
- `ix_audit_log_action_created_at` (`action`, `created_at`): filter by action in the admin console.

### `idempotency_records`

Module `core` (`motionile.core.idempotency`) · Phase 2 · Mutable

Stores the outcome of requests sent with an `Idempotency-Key` header so retries replay the original response.

| Column             | Type          | Null | Default         | Notes                                                                                                            |
| ------------------ | ------------- | ---- | --------------- | ---------------------------------------------------------------------------------------------------------------- |
| `id`               | `uuid`        | no   | -               | UUIDv7                                                                                                           |
| `scope`            | `text`        | no   | -               | Operation name, such as `billing.order.create`, at most 100 characters                                           |
| `user_id`          | `uuid`        | yes  | -               | Caller; null for unauthenticated endpoints                                                                       |
| `key`              | `text`        | no   | -               | Client-supplied key: 1 to 255 visible ASCII characters                                                           |
| `request_hash`     | `bytea`       | no   | -               | SHA-256 of method, path and canonical body                                                                       |
| `status`           | `text`        | no   | `'in_progress'` | `in_progress`, `completed`                                                                                       |
| `response_status`  | `smallint`    | yes  | -               | Set when completed                                                                                               |
| `response_body`    | `jsonb`       | yes  | -               | Replayed body                                                                                                    |
| `response_headers` | `jsonb`       | yes  | -               | Replayed headers such as `Location`; added because a replay must be indistinguishable from the original response |
| `locked_until`     | `timestamptz` | yes  | -               | In-flight lease; another request with the same key gets 409 with `Retry-After` until then                        |
| `expires_at`       | `timestamptz` | no   | -               | When the record can be purged (24 hours by default)                                                              |
| `created_at`       | `timestamptz` | no   | `now()`         |                                                                                                                  |
| `updated_at`       | `timestamptz` | no   | `now()`         |                                                                                                                  |

Keys and constraints:

- `pk_idempotency_records` primary key (`id`).
- `fk_idempotency_records_user_id_users` → `users.id` **ON DELETE CASCADE**, added by Phase 4.
- `uq_idempotency_records_scope_user_id_key` unique (`scope`, `user_id`, `key`) **NULLS NOT DISTINCT**.
- `ck_idempotency_records_status`: `status IN ('in_progress', 'completed')`.
- `ck_idempotency_records_scope_length`: `char_length(scope) BETWEEN 1 AND 100`.
- `ck_idempotency_records_key_format`: `key ~ '^[\x21-\x7E]{1,255}$'`.
- `ck_idempotency_records_request_hash_length`: `octet_length(request_hash) = 32`.
- `ck_idempotency_records_response_status_range`: `response_status IS NULL OR response_status BETWEEN 100 AND 599`.
- `ck_idempotency_records_completed_has_response`: `status <> 'completed' OR response_status IS NOT NULL`.
- `ck_idempotency_records_in_progress_has_lock`: `status <> 'in_progress' OR locked_until IS NOT NULL`.

Indexes:

- The unique constraint serves the lookup by (`scope`, `user_id`, `key`).
- `ix_idempotency_records_user_id` (`user_id`): supports the foreign key.
- `ix_idempotency_records_expires_at` (`expires_at`): retention purge.

### `user_contacts`

Module `users` · Phase 4 · Mutable

Email addresses and phone numbers that identify a user and receive OTPs.

| Column        | Type          | Null | Default | Notes                                      |
| ------------- | ------------- | ---- | ------- | ------------------------------------------ |
| `id`          | `uuid`        | no   | -       | UUIDv7                                     |
| `user_id`     | `uuid`        | no   | -       |                                            |
| `kind`        | `text`        | no   | -       | `email`, `phone`                           |
| `value`       | `citext`      | no   | -       | Email (case-insensitive) or phone in E.164 |
| `verified_at` | `timestamptz` | yes  | -       | Null until an OTP is confirmed             |
| `is_primary`  | `boolean`     | no   | `false` | Where notifications go for this kind       |
| `created_at`  | `timestamptz` | no   | `now()` |                                            |
| `updated_at`  | `timestamptz` | no   | `now()` |                                            |

`value` is `citext` for both kinds: E.164 phone numbers contain no letters, so case-insensitivity is harmless and one column keeps lookups uniform.

Keys and constraints:

- `pk_user_contacts` primary key (`id`).
- `fk_user_contacts_user_id_users` → `users.id` **ON DELETE CASCADE**.
- `uq_user_contacts_user_id_kind_value` unique (`user_id`, `kind`, `value`): a user cannot add the same contact twice.
- `ck_user_contacts_kind`: `kind IN ('email', 'phone')`.
- `ck_user_contacts_email_format`: `kind <> 'email' OR (value ~ '^[^@\s]+@[^@\s]+\.[^@\s]+$' AND char_length(value) <= 254)`.
- `ck_user_contacts_phone_format`: `kind <> 'phone' OR value ~ '^\+[1-9][0-9]{6,14}$'`.

Indexes:

- `ix_user_contacts_kind_value_verified` unique (`kind`, `value`) `WHERE verified_at IS NOT NULL`: a verified contact belongs to exactly one user; serves login lookup.
- `ix_user_contacts_user_id_kind_primary` unique (`user_id`, `kind`) `WHERE is_primary`: at most one primary contact per kind per user.
- `ix_user_contacts_kind_value` (`kind`, `value`): lookup of unverified contacts during registration and the `verification_required` login path.
- The unique constraint's leading `user_id` column supports the foreign key.

Unverified duplicates across users are allowed; the first user to verify a contact wins and later verifications fail with a conflict.

### `sessions`

Module `auth` · Phase 4 · Mutable

One row per refresh token. Rotation inserts a child row with the same `family_id` and marks the parent `rotated_at`.

| Column                | Type          | Null | Default | Notes                                                                                   |
| --------------------- | ------------- | ---- | ------- | --------------------------------------------------------------------------------------- |
| `id`                  | `uuid`        | no   | -       | UUIDv7; the first row also identifies the family                                        |
| `family_id`           | `uuid`        | no   | -       | The JWT `sid`; shared by every rotation of one login                                    |
| `user_id`             | `uuid`        | no   | -       |                                                                                         |
| `token_hash`          | `bytea`       | no   | -       | SHA-256 of the opaque refresh token                                                     |
| `parent_id`           | `uuid`        | yes  | -       | Session this one rotated from                                                           |
| `rotated_at`          | `timestamptz` | yes  | -       | When this token was exchanged for a child                                               |
| `revoked_at`          | `timestamptz` | yes  | -       |                                                                                         |
| `revoke_reason`       | `text`        | yes  | -       | `logout`, `logout_all`, `reuse_detected`, `password_changed`, `admin`, `user_suspended` |
| `idle_expires_at`     | `timestamptz` | no   | -       | `min(now + 7 days, absolute_expires_at)`                                                |
| `absolute_expires_at` | `timestamptz` | no   | -       | Login time plus 60 days, copied to every rotation                                       |
| `ip`                  | `inet`        | yes  | -       |                                                                                         |
| `user_agent`          | `text`        | yes  | -       | At most 512 characters                                                                  |
| `device_label`        | `text`        | yes  | -       | Derived from the user agent, at most 120 characters                                     |
| `last_used_at`        | `timestamptz` | no   | `now()` |                                                                                         |
| `created_at`          | `timestamptz` | no   | `now()` |                                                                                         |
| `updated_at`          | `timestamptz` | no   | `now()` |                                                                                         |

Keys and constraints:

- `pk_sessions` primary key (`id`).
- `fk_sessions_user_id_users` → `users.id` **ON DELETE CASCADE**.
- `fk_sessions_parent_id_sessions` → `sessions.id` **ON DELETE SET NULL**.
- `uq_sessions_token_hash` unique (`token_hash`): refresh lookup.
- `ck_sessions_token_hash_length`: `octet_length(token_hash) = 32`.
- `ck_sessions_expiry_order`: `idle_expires_at <= absolute_expires_at`.
- `ck_sessions_revoke_reason`: `revoke_reason IS NULL OR revoke_reason IN ('logout', 'logout_all', 'reuse_detected', 'password_changed', 'admin', 'user_suspended')`.
- `ck_sessions_revocation_consistent`: `(revoked_at IS NULL) = (revoke_reason IS NULL)`.
- `ck_sessions_user_agent_length`: `user_agent IS NULL OR char_length(user_agent) <= 512`.

Indexes:

- `ix_sessions_user_id_created_at` (`user_id`, `created_at`) `WHERE revoked_at IS NULL AND rotated_at IS NULL`: active sessions list and "revoke all"; the full foreign key is covered by `ix_sessions_user_id`.
- `ix_sessions_user_id` (`user_id`): supports the foreign key.
- `ix_sessions_family_id` (`family_id`): revoke a whole family on reuse.
- `ix_sessions_parent_id` (`parent_id`): supports the foreign key.
- `ix_sessions_absolute_expires_at` (`absolute_expires_at`): retention purge.

## Billing and credits

Billing tables reference `users` with `ON DELETE RESTRICT`: financial records must outlive the account (see `retention.md`). A user with financial history is anonymized, never hard-deleted. The `billing` module owns `products`, `billing_customers`, `orders`, `payments`, `subscriptions`, `refunds`, `webhook_events` and `billing_reconciliation_runs`. The `credits` module owns `credit_wallets`, `credit_lots`, `credit_reservations`, `credit_ledger` and `usage_records`. `billing` reaches credits only through `motionile.modules.credits`.

### Credit invariants

For every user, at every committed point in time:

1. `credit_wallets.balance` equals the sum of `credit_ledger.delta` and the sum of `credit_lots.remaining`.
2. `credit_wallets.reserved` equals the sum of `credit_ledger.reserved_delta` and the sum of `credit_reservations.amount` where `status = 'active'`.
3. The newest ledger row's `balance_after` and `reserved_after` equal the wallet's `balance` and `reserved`.
4. `0 <= reserved <= balance`, and no lot has a negative `remaining`.

Every operation locks the wallet row first, then the lots it touches ordered by `expires_at NULLS LAST, created_at, id`, then writes lots, reservation, wallet and exactly one ledger row in one transaction. The nightly integrity task verifies all four invariants for every wallet.
