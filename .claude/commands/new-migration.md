description: Create one reversible expand/contract Alembic migration following the database conventions
argument-hint: <short description of the schema change>
---

Create a migration for: $ARGUMENTS

1. Read `docs/db/conventions.md` and the database rules in `docs/context.md` section 6.
2. Check `git diff develop --stat -- apps/server/migrations/versions`. If this branch already adds a migration, extend that one instead; each pull request ships at most one.
3. Update the SQLAlchemy models first, then run from `apps/server`: `uv run alembic revision --autogenerate -m "<description>"`.
4. Edit the generated file so it:
   - uses UUIDv7 primary keys generated by the application, `created_at` and `updated_at` as `timestamptz`,
   - stores statuses as `text` with a named `CHECK` constraint, money and credits as `bigint`,
   - indexes every foreign key and sets `ON DELETE` explicitly,
   - only expands the schema (new tables, nullable columns, new indexes created concurrently where needed) or only contracts what no deployed code still reads,
   - has a complete `downgrade()` that reverses `upgrade()`,
   - contains no comments.
5. Add or extend an integration test proving `upgrade head`, `downgrade -1` and `upgrade head` succeed.
6. Run `pnpm test:integration` and `pnpm verify`.
7. Report the revision ID, the tables and constraints touched, and whether it is an expand or a contract step.
